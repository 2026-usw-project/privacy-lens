# vision — YOLO 검출 지속 학습 (YOLO26)

팀원 누구나 **사진이 생기면 넣고, 검수하고, 학습**할 수 있게 만든 도구입니다.
사진·라벨·모델은 git 이 아니라 **팀 구글 드라이브 공유 폴더**에 모읍니다(실사 이미지 커밋 금지 규칙).

```
 촬영 ──▶ inbox ──[ingest]──▶ review ──[라벨 검수]──▶ [build] ──▶ dataset ──[train]──▶ models
 (누구나)  사진 넣기   EXIF 삭제·중복 제거      label_tool.html      검수본만        더 나으면 current 교체
                       초벌 라벨(현재 모델)                                              │
                          ▲──────────────────────────────────────────────────────────────┘
                          모델이 좋아질수록 초벌 라벨이 정확해져 검수가 빨라진다
```

- **ingest·build·train** 은 Colab 노트북(`vision/colab.ipynb`)이나 내 PC 명령어 어느 쪽으로든 실행합니다. 결과는 같은 드라이브 폴더에 쌓입니다.
- **라벨 검수**는 내 PC 크롬에서 공유 폴더의 `라벨검수도구.html` 을 열어 합니다. 저장소를 받지 않아도 되고, 사진은 내 컴퓨터 밖으로 나가지 않습니다.
- 지금은 **학습 환경까지**입니다. 서비스(`pipeline/`)에 검출기를 붙이는 일은 별도 PR 로 합니다.

## YOLO26 과 역할 전환 (2026-11-02, D-16)

- **모델**: 기본 시작 가중치를 `yolo11n.pt` → `yolo26n.pt` 로 바꿨습니다(`ultralytics>=8.4` 필요).
  YOLO11 로 학습한 예전 모델(v001~v004)은 구조가 달라 이어서 학습할 수 없어서, 다음 학습은 자동으로 `yolo26n.pt` 부터 새로 합니다.
  실사 검증 사진이 없으면 교체가 막히므로 **첫 YOLO26 모델만 `--force`** 로 올립니다(Colab 4번 칸 `FORCE = True`).
  모델의 계열은 `models/vNNN/metrics.json` 의 `family`, 서비스 화면 하단(`YOLO v005·yolo26`)에 보입니다.
- **역할**: 팀 실사 시험에서 OCR 만으로 책장 위 신분증 글자까지 읽혀, YOLO 는 **글자가 아닌 이미지 객체**
  (증명사진·얼굴·번호판·보안 표식 등) 쪽으로 옮기기로 했습니다. 아래 문서 클래스(송장·카드·명찰·화면)는 **지금 모델로 동결**하고
  새 학습 투자는 하지 않습니다. 새 클래스 목록은 D-16 미결 항목에서 정합니다(클래스는 맨 뒤에만 추가).

3. 일상 사진 9종(D-19): 드라이브 `objects/daily_v001/best.onnx`(2026-11-08, 해외 공개 데이터 검증 mAP50 0.535, VizWiz-Priv 빠진 데이터로 학습)를

#### v003 과 사진 방향 (2026-11-03, 노트북 10번 칸 + `orientation_report`)

v003 = v002 에서 이어 학습. Open Images 2,000 + **합성 1,644장**(`vision/plate_synth.py`: 한국 번호판 조각 2,168개를 Open Images 차량 장면 번호판 자리에 붙임, 20% 는 원래 번호판 유지) + 한국 근접 사진. 검증에 한국 test 분할을 섞고 20 epoch, 마지막 가중치.

**평가 사진의 30% 가 누워 있다.** hyunjin 207장 중 61장은 휴대폰 회전 정보(EXIF) 없이 90도 누운 채 올라와 있다(번호판이 세로로 긺, EXIF 회전 정보 0장).
서비스는 EXIF 를 적용해 바로 세우므로 '바로 선 사진'이 실제 사용에 가깝다. 다만 메신저처럼 회전 정보를 지우는 경로로 온 사진은 정말 누워서 들어온다.

| 확신도 0.4 재현율 (정밀도) | 바로 선 146장 (번호판 179) | 누운 61장 그대로 (80) | 한국 전체 | Open Images |
|---|---|---|---|---|
| 공개 모델 | 0.743 (0.930) | 0.075 | 0.537 | 0.744 |
| v001 | 0.704 (0.851) | 0.013 | 0.490 | 0.866 |
| v002 | 0.816 (0.869) | 0.200 | 0.626 | 0.824 |
| **v003** | **0.827** (0.861) | 0.150 | 0.618 | **0.859** |
| **v003 + 돌려 찾기(0·90·270)** | **0.838** (0.820) | **0.663** (0.697) | **0.784** (0.784) | 0.859 (0.894) |

- **v003 을 기본으로 추천**: 바로 선 한국 사진에서 가장 높고, v002 에서 떨어졌던 해외 재현율도 v001 수준(0.859)으로 돌아왔다.

- **누운 사진은 모델을 바꿔도 안 된다**(0.15~0.2). 그래서 `PlateDetector` 가 사진을 90·270도 돌려서도 찾게 했다(`PL_PLATE_ROTATE`, 기본 켬).

- 누운 사진을 바로 세웠을 때(두 방향 중 맞는 쪽)도 0.56~0.61 로, 바로 선 사진(0.83)보다 낮다. 이 사진들은 세로 사진을 640×640 으로 늘린 것이라 번호판 모양이 찌그러졌다.
- 놓친 번호판 모음: 드라이브 `objects/kr_missed_v002.jpg`. 결과 파일: `objects_eval_v003.json`, `objects_eval_orientation.json`, `objects_eval_rotate.json`.

#### 증명사진 얼굴 (2026-11-03, `vision/face_eval.py`, MIDV-2020)

Open Images 얼굴(사람 사진)은 우리 쓰임새와 다르다. 사진 속 신분증의 **증명사진**을 재려고 MIDV-2020 photo(가상 신분증 10종을 휴대폰으로 찍은 1,000장,
CC BY-SA 2.5, 얼굴은 생성 얼굴, `ftp://smartengines.com/midv-2020`)을 썼다. 정답은 인쇄 얼굴 타원이라 IoU 0.3 기준. 사진을 줄여(멀리 찍힌 신분증) 잰다.

| YuNet 점수 0.6 (300장) | 얼굴 짧은 변 | 재현율 | 정밀도 |
|---|---|---|---|
| 그대로 | 260px | 0.763 | 0.676 |
| 1/4 로 줄임 | 65px | 0.750 | 0.824 |
| 1/8 로 줄임 | 32px | 0.650 | 0.970 |
| 90도 누움(1/2) | 130px | **0.130** | 0.285 |

**누운 사진에서 거의 못 찾아** 얼굴도 0·90·270도로 찾게 했다(`PL_FACE_ROTATE`, 기본 켬). 같은 조건 150장 비교(점수 0.6):

| | 그대로 원본 | 그대로 1/4 | 누움 원본 | 누움 1/4 |
|---|---|---|---|---|
| 돌려 찾기 끔 | 0.82 (0.81) | 0.80 (0.92) | 0.11 (0.37) | 0.04 (0.21) |
| **돌려 찾기 켬** | 0.82 (0.71) | 0.80 (0.77) | **0.82** (0.70) | **0.80** (0.78) |

(재현율, 괄호는 정밀도)
- 누운 사진 재현율 0.04~0.11 → 0.80~0.82. 바로 선 사진 재현율은 그대로, 정밀도는 0.1 정도 떨어지고 얼굴 검출 시간은 약 3배.
  기본 모드(card)는 카드 단서가 있어야 알리므로 늘어난 오탐이 그대로 화면에 나가지는 않는다.
- 바로 선 사진에서도 18~24% 를 놓친다. 정밀도가 낮은 것은 신분증의 작은 보조 사진(유령 사진)을 찾은 것도 오탐으로 세서일 수 있다(확인 안 함).
- 다음 후보: MIDV-2020 으로 YOLO26 증명사진(face_photo) 클래스 학습(`python -m vision import-midv`), 한국 신분증·학생증 실사로 다시 재기.

## 1. 사진 넣기 — 누구나

`inbox/` 안에 **묶음 폴더**를 만들어 넣습니다. 폴더 이름은 `이름_소품_날짜` 처럼 씁니다.

```
inbox/찬영_학생증A_1007/IMG_0001.jpg ...
inbox/다인_송장3종_1008/...
```

- **묶음 = 같은 소품·같은 장소에서 찍은 사진들**입니다. 학습/검증/시험 분할을 묶음 단위로 해서, 같은 학생증이 학습과 시험에 동시에 들어가지 않게 합니다. 묶음을 너무 크게 만들지 마세요(10~30장 권장).
- 휴대폰 원본(JPG·HEIC) 그대로 넣으면 됩니다. 위치정보는 ingest 때 지워지고, inbox 원본도 그때 삭제됩니다.

**촬영 규칙**
- **가상 정보로 만든 소품만** 찍습니다. 실제 내 학생증이나 타인의 개인정보가 보이면 안 됩니다(PRD 데이터 윤리).
- 같은 소품을 **거리(가까이·멀리), 각도, 조명, 배경, 흔들림**을 바꿔 가며 찍습니다. 사진 속에서 작게 나오는 경우가 특히 중요합니다.
- **물체가 없는 사진도** 일부 넣습니다(책상, 책 표지, 간판 등). 오탐을 줄이는 데 쓰입니다.
- 사람이 겨우 읽을 정도로 흐린 사진도 넣습니다. 교수님 피드백 "사람은 읽는데 OCR 이 못 읽는 경우"를 잡으려는 데이터입니다.

## 3. 라벨 검수 — 누구나

1. 공유 폴더의 **`라벨검수도구.html`**(= `vision/label_tool.html` 사본)을 **크롬이나 엣지**로 엽니다. 파일을 브라우저 창에 끌어다 놓으면 됩니다.
2. **폴더 열기** → `PrivacyLens-YOLO` (또는 그 안의 `review`) 를 고르고 편집 권한을 허용합니다.
3. 초벌 박스를 고치고 **Enter**(검수 완료) / 쓸 수 없는 사진은 **X**(제외).

| 조작 | 키 |
|---|---|
| 새 박스 | 빈 곳 드래그 (선택된 클래스로) |
| 클래스 선택·변경 | 1 ~ 6 |
| 박스 이동·크기 | 박스 드래그 / 모서리 드래그 |
| 삭제 / 되돌리기 | Delete / Ctrl+Z |
| 확대 / 이동 / 맞춤 | 휠 / Space+드래그·오른쪽 드래그 / F |
| 이전·다음 | ← → (고친 박스는 저장됨, 완료 표시는 안 됨) |

- 물체가 하나도 없는 사진도 **그대로 Enter** 합니다.
- 두 사람이 같은 사진을 동시에 검수하지 않게, 단톡방에 "검수 시작"을 알리거나 나눠서 합니다.
- 데스크톱 앱이 없으면: 드라이브에서 `review` 폴더를 내려받아 검수한 뒤 `labels/` 와 `done/` 폴더를 다시 올립니다.
- 데스크톱 앱은 저장한 파일을 몇십 초~몇 분 뒤에 드라이브로 올립니다. 동기화가 끝나기 전에 build 를 돌리면 완료 표시를 못 봅니다.

### 애매한 경우

| 경우 | 기준 |
|---|---|
| 사진 밖으로 잘림·다른 물건에 가려짐 | 보이는 부분만 박스 |
| 아주 작게 찍힘 | 글자는 못 읽어도 **무슨 물건인지 알아볼 수 있으면** 박스. 검출기를 쓰는 이유가 이 경우다 |
| 기울어진 문서 | 전체를 감싸는 똑바른 사각형 |
| 카드 안 증명사진, 송장·카드 안 바코드 | 카드·송장 박스와 **따로 겹쳐서** 하나 더. 바코드가 여러 개면 각각 |
| 꺼진 화면, 글자가 안 보이는 화면 | 박스 안 함 |
| 이름 줄·번호 줄 같은 항목 하나하나 | 박스 안 함. 항목은 OCR 과 규칙이 찾는다 |
| 흐림·반사가 심함 | 알아볼 수 있으면 박스, 아니면 사진 제외(X) |
| 휴대폰에 띄운 모바일 학생증 | **팀 결정 필요**: 화면(4)만 칠지, 학생증(2)도 겹쳐 칠지 |

### 자동 점검

검수는 한 번(Enter)으로 끝냅니다. 대신 build 가 다음을 자동으로 점검합니다. 막힌 사진은 완료 표시가 지워지고 검수 폴더에 남습니다.

| 막음 | 경고만 |
|---|---|
| 형식 오류(숫자 아님, 없는 클래스, 좌표 범위 밖) | 증명사진이 학생증·카드 박스 밖에 있음 |
| 6px보다 작은 박스(클릭 실수) | 박스가 사진 거의 전체 |
| 같은 클래스 박스를 두 번 그림 | |

라벨을 한눈에 훑어보고 싶을 때는 `python -m vision sheet` 로 묶음별 썸네일 시트(`검수시트/`)를 만들 수 있습니다(선택).

## 4. 데이터셋 반영 + 학습 — 누구나 (GPU 있는 사람 또는 Colab)

```bash
python -m vision build --who 찬영     # 검수 완료(.ok)만 dataset 으로. 미검수 초벌 라벨은 절대 학습에 안 씀
python -m vision train --who 찬영     # GPU 자동 사용. --epochs 60 --imgsz 1280 기본
```

- 학습은 **지금 모델(current)에서 이어서** 합니다.
- 끝나면 새 모델과 지금 모델을 **같은 시험 사진**으로 다시 채점해서, 같거나 좋을 때만 `current` 로 바꿉니다. 나빠진 모델은 `models/vNNN/` 에 남기만 합니다(`--force` 로 강제 교체 가능).
- 기록은 `models/history.csv`, 버전별 상세는 `models/vNNN/metrics.json`(클래스별 AP50 포함).
- 시험 점수는 **직접 찍은 사진(val·test)으로만** 냅니다. 합성 사진은 학습에만 씁니다. 실사 묶음이 3개 미만이면 검증 데이터가 없어 점수가 의미 없다는 경고가 나옵니다.

## 공개 데이터 더하기 — MIDV-2020 (학생증·카드류)

[MIDV-2020](https://l3i-share.univ-lr.fr/MIDV2020/midv2020.html) 은 **가상 정보로 만든 신분증·여권 1,000종을 실제로 촬영한** 연구용 데이터셋입니다. 얼굴도 생성된 얼굴이라 실제 개인정보가 없습니다. 한국 학생증은 아니지만 "카드가 사진 어디에 있나"를 배우는 데 도움이 됩니다.

1. 위 페이지의 신청서를 작성하고 라이선스에 동의해 내려받습니다(신청은 사람이 직접). `photo.tar` 만 받으면 됩니다.
2. 압축을 풀고 가져옵니다.

```bash
python -m vision import-midv "D:/MIDV2020/photo" --who 찬영           # 전부(1,000장)
python -m vision import-midv "D:/MIDV2020/photo" --limit 30           # 종류마다 30장만
```

- 문서 네 꼭짓점(`doc_quad`) → **학생증·카드**, 얼굴 영역(`face`) → **증명사진**(사진 테두리에 가깝게 조금 넓힘)으로 바뀝니다.
- 합성 사진처럼 **학습에만** 쓰고, 점수는 팀이 찍은 한국 실사로만 냅니다. 현황의 `공개` 칸에 따로 셉니다.
- 라이선스 조건을 따라 **공유 폴더 밖으로 재배포하지 않습니다.** 저장소에도 올리지 않습니다.
- 공개 사진이 실사보다 훨씬 많으면 모델이 외국 신분증에 치우칠 수 있습니다. 처음엔 `--limit 30`(약 300장) 정도로 시작하는 것을 권합니다.

## 배경 사진 더하기 — 공개·AI 배경

물체 없는 배경 사진(책장·책상·선반·방)을 **학습 전용·빈 라벨**로 넣습니다. 오탐을 줄이는 데 쓰이고, 합성 생성기가 이 사진들 위에도 카드를 붙입니다(실제 배경 속 작은 카드).

```bash
python -m vision import-bg "<배경 사진 폴더>" --who 찬영
```

- 공개 사진(Open Images 등, 라이선스·출처 기록 필요)이나 AI 로 만든 배경용입니다. 직접 찍은 배경은 평소처럼 `inbox` 로 넣고 박스 없이 Enter 하면 됩니다.
- `ingest` 로 넣으면 '직접 촬영'으로 분류되어 검증·시험에 섞이므로 꼭 `import-bg` 로 넣습니다.
- **송장·학생증·명찰·글자 보이는 화면·바코드가 찍힌 사진은 빼세요.** 넣으면 그것들을 배경으로 잘못 배웁니다.
- Colab 에서는 공유 폴더 `배경/` 에 zip 을 올리고 "(선택) 배경 사진 넣기" 칸을 실행합니다.

## 개인 폴더 사진 더하기 — AI 허브 등

AI 허브 데이터는 **승인받은 본인만** 쓸 수 있어서 공유 폴더(dataset)에 넣으면 안 됩니다. 대신 학습할 때만 내 개인 폴더의 사진을 섞습니다. 공유 dataset·manifest 에는 아무것도 남지 않고, 학습된 모델(`models/vNNN`)은 공유해도 됩니다(AI 허브 이용 조건상 학습으로 만든 결과물은 활용 가능).

```bash
python -m vision train --who 찬영 --extra "/content/drive/MyDrive/AIHub-개인/yolo-extra" --extra-limit 300
```

- 폴더 구조: `images/` 에 사진, 필요하면 `labels/<같은 이름>.txt`(YOLO 형식). **라벨이 없으면 물체 없는 배경**으로 배웁니다.
- 배경으로 넣는 사진에 우리 클래스(송장·학생증·명찰·화면·증명사진·바코드/QR)가 찍혀 있으면 "그건 배경"이라고 잘못 배웁니다. QR·바코드가 보이는 간판 사진은 빼고 넣습니다.
- `--extra-limit` 으로 장수를 제한합니다. 배경 사진이 실사보다 훨씬 많으면 문서를 덜 찾게 될 수 있으니, 처음엔 학습 사진 수와 비슷하거나 적게 넣습니다.
- 섞은 폴더 이름과 장수는 `models/vNNN/metrics.json` 의 `extra` 에 남습니다. 보고서·발표에는 "한국지능정보사회진흥원의 사업결과" 출처를 밝힙니다.
- 다른 팀원이 같은 데이터를 쓰려면 그 사람도 AI 허브에서 직접 승인받아야 합니다.

## 검출기 효과 재기 — 전후 비교

같은 사진을 **검출 없음**(지금 서비스)과 **검출 있음**으로 돌려, 정답 문서(송장·학생증·명찰·화면)를 몇 개나 알렸는지 크기별로 비교합니다. OCR 이 필요합니다(PaddleOCR).

```bash
PL_OCR=paddleocr python -m eval.detector <폴더> --weights <작업폴더>/models/v003/best.pt
```

- `<폴더>` 에는 `images/` 와 `labels/` 가 있어야 합니다.
- **최종 시험 묶음**은 학습 작업 폴더와 다른 작업 폴더에서 처리합니다. 학습에 절대 섞이지 않게 하려는 것입니다.

  ```bash
  python -m vision ingest --root "<작업폴더>/최종시험"   # 최종시험/inbox/ 에 사진을 넣고
  # 라벨 도구로 최종시험 폴더를 열어 검수
  python -m vision build  --root "<작업폴더>/최종시험"
  PL_OCR=paddleocr python -m eval.detector "<작업폴더>/최종시험/dataset" --weights …
  ```

- 나오는 것: 알린 문서(작음·중간·큼), 그중 내용까지 읽은 문서, 엉뚱한 곳의 경고 수, 처리 시간, 놓친 문서 이름.
- 항목(이름·번호) 단위 정답은 라벨에 없어서 재지 않습니다. 참고(info) 항목만 있는 문서는 "알리지 않음"으로 셉니다.
- 학습·검수에 쓴 사진으로 재면 "검출 있음"이 부풀려집니다. 발표 숫자는 봉인한 시험 묶음으로 냅니다.

## 자주 묻는 것

- **"다른 사람이 작업 중입니다"** — 동시에 돌리면 `manifest.csv` 가 꼬여서 막아 둔 것입니다. 3시간이 지나면 자동으로 풀리고, 확실히 아무도 안 쓰면 `작업중.lock` 을 지워도 됩니다.
- **클래스를 추가하고 싶다** — `classes.py` 맨 뒤에 추가 → `python -m vision init` (검수 도구 목록 갱신) → 기존 모델과 클래스가 달라 `yolo26n.pt` 부터 다시 학습됩니다.
- **같은 사진을 또 넣었다** — 파일 내용 해시로 걸러지므로 한 장만 남습니다.
- **Colab 세션이 끊겼다** — 학습 칸만 다시 실행합니다. 끊긴 학습은 저장되지 않고, 데이터는 드라이브에 그대로 있습니다.

## 참고

- 학습 라이브러리 Ultralytics(YOLO26)는 **AGPL-3.0** 입니다. 공개 저장소에서 수업 프로젝트로 쓰는 데는 문제없지만, 상용 배포 시에는 라이선스를 다시 확인해야 합니다.
- 합성 생성기(`vision/synth.py`, 생성기 3)는 한국에서 볼 법한 모양을 본뜬 가상 물체를 그립니다. 송장 3종(가로형·세로형·소형 스티커), 학생증(가로·세로·밝은 카드, 사진 오른쪽·잔무늬·반사광, 증명사진은 실루엣이나 단순한 그림 얼굴), 명찰 3종(가슴·행사·책상), 화면(휴대폰·모니터에 가짜 메신저·주문내역·택배 조회·메일, 화면 부분만 박스), 송장이 아닌 서류(박스 없음)입니다. 40% 는 사진 짧은 변의 5~20% 로 작게, 30% 는 기대 세운 원근, 35% 는 책등·물건에 일부 가려지게 붙이고 박스는 보이는 부분만 잡습니다. 데이터셋에 물체 없는 실사 사진(책장·책상 배경 등)이 있으면 절반은 그 위에 붙입니다. 실제 택배사·학교 이름과 로고, 특정 신분증 디자인은 쓰지 않습니다. 생성기가 바뀔 때마다 이름이 `syn3_…` 처럼 달라져 합성 칸을 다시 실행하면 새 사진이 더해집니다.
