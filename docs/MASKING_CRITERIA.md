# 가림 기준표 (초안, 2026-11-01)

판단 코드(`pipeline/context.py`)와 판단 평가(`eval/judgment.py`)가 따르는 기준이다.
**팀 합의 전 초안**이다. 바꾸면 `eval/judgment.py` 의 정답도 같이 바꾼다.

## 원칙

1. **혼자서 특정 개인을 알아볼 수 있거나, 다른 정보와 합쳐 그렇게 되는 것**을 가린다.
2. **놓침이 오탐보다 나쁘다.** 애매하면 '확인 필요'로 올린다. 단, '가림'으로 단정하지는 않는다.
3. **공개된 정보**(가게·기업이 일부러 알리는 번호·주소·상호)는 가리지 않는다.
4. 판단 근거(옆의 라벨, 문서 종류)를 사용자에게 보여 줄 수 있어야 한다.

## 팀이 정해야 할 것 (미결)

- **라벨 없는 이름 후보를 '확인 필요'로 올릴지.** 올리면 놓침이 줄고 오탐(상호·지명)이 늘어난다. 초안은 올리는 쪽이다.
- **학교·회사명 단독**을 확인 필요로 볼지. 초안은 이름 옆일 때만 본다.
- 메신저 캡처 속 **대화 상대 이름**(화면 위쪽 대화방 제목)도 같은 기준인지.
- 영수증의 **일부 가려진 카드번호**는 무시해도 되는지.
- **번호를 못 읽은 결제 카드**(양각·카드와 같은 색 번호): 9종 모델이 카드를 찾았는데 카드번호 항목이 없으면 카드째 가림 권장으로 둔다(2026-11-14, 팀 확인 필요).
- 대형 택배사 송장처럼 **가운데가 가려진 이름(홍\*동)·전화(010-\*\*\*\*-1234)**. 촬영 소품(`samples/props.py`)은 임시로 이름=확인 필요, 전화=가리지 않음으로 둔다.
- 배달 주문서의 **안심번호(0507-…)**, 우편물 **등기번호**. 소품은 임시로 확인 필요(`기타`)로 둔다.
- 화면이 지금 **'가림' 등급도 기본으로 선택하지 않는다**(`web/frontend-demo/dist/core.js`, `enabled:false`).
  위 원칙 2(놓침이 더 나쁨)와 맞추려면 '가림'은 기본 선택, '확인 필요'는 기본 해제가 맞다. 문서화된 결정이 없어 그대로 두었다.

## 구현 상태 (2026-11-01)

위 표의 가림·확인 필요는 `pipeline/context.py` 에 구현돼 있다. 증명사진은 YOLO 검출(선택)에서만 나온다.
- 이름처럼 생겼는지는 `kr_patterns.name_candidate`(성 + 흔한 이름 글자, 장소·가게 꼬리말 제외)로 본다.
  따로 모은 목록(`python -m eval.names_check`)에서 이름 100개 중 100개, 일반 낱말 95개 중 12개(13%)를 후보로 골랐다.
  이름 쪽은 목록을 보고 글자 두 개(후·결)를 추가했으므로 100% 는 부풀려진 숫자다.
- 단서 없는 이름 후보를 확인 필요로 올리면(`all`) 가상 장면의 '가리면 안 될 것' 182개 중 8개(4.4%)가 잘못 확인 요청된다.

## 측정

- 판단만: `python -m eval.judgment` (가상 텍스트 장면, OCR 완벽 가정). `--unlabeled-names off|context|all` 로 D-12 비교
- 이름 후보 판정만: `python -m eval.names_check`, 규칙 vs NER: `python -m eval.ner_compare`
