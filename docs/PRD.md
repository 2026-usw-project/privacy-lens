# Privacy Lens PRD

- 상태: v0.1 초안 (2026-10-01)
- 기준 자료: ① 1차 발표 자료(2026-09-16) ② 5인 역할 분담안 ③ `schema/` v0.1.0
- 자료끼리 다르거나 아직 정해지지 않은 부분은 [DECISIONS.md](DECISIONS.md)에 모아 두었습니다. 이 문서의 `(D-xx)`는 그 항목을 가리킵니다.

## 1. 한 줄 요약

사진을 SNS·중고거래 등에 올리기 전에, 배경에 함께 찍힌 개인정보(택배 송장의 주소·연락처, 학생증의 이름, 모니터 속 대화 등)를 AI로 찾아 **위치와 근거**를 보여 주고, 사용자가 확인한 영역을 클릭 한 번으로 가린 뒤 **촬영 위치 같은 메타데이터(EXIF)까지 제거한 사진**을 저장하게 해 주는 웹 서비스입니다.

수원대학교 정보보호학과 2026학년도 2학기 시스템보안프로젝트이며, 5인 팀이 7주(발표안 기준) 동안 진행합니다.

## 2. 배경과 문제

- 사용자는 사진의 주요 피사체에 집중하기 때문에 배경에 찍힌 택배 송장, 학생증, 모니터 화면, 번호판을 놓치기 쉽습니다.
- 공개한 사진은 캡처·재배포로 퍼져서 원본 게시물을 지워도 사본까지 회수하기 어렵습니다. 그래서 **공개하기 전** 검사가 필요합니다.
- 기존 도구는 문제의 일부만 다룹니다.

| 도구 | 하는 일 | 한계 |
|---|---|---|
| 수동 모자이크·블러 | 사용자가 지정한 영역을 가림 | 위험한 곳을 사용자가 직접 찾아야 함 |
| SNS 얼굴 블러 | 얼굴을 찾아 가림 | 문서·화면·번호판은 별도 확인이 필요함 |
| EXIF 제거 도구 | 메타데이터를 삭제 | 사진에 찍힌 정보는 그대로 남음 |
| 기업용 DLP | 기업 문서 스캔 중심 | 일상 사진·배경 소물체 대응은 별도 검토가 필요함 |

**차별점(발표안)**

1. 한국 특화 — 택배 송장·학생증 같은 대상과 한국 주소 체계를 다룹니다.
2. 배경 소물체 — 작은 글자를 원본 해상도로 판독해, 사진을 줄이면서 생기는 정보 손실을 줄입니다.
3. 설명 가능한 결과 — 점수만 주지 않고 어디서 무엇이 왜 위험한지 위치와 근거 문장으로 보여 줍니다.

## 3. 목표와 비목표

**목표**

- G1. 공유 전 사진에서 개인정보 노출 위험을 자동으로 찾아 위치·유형·근거를 보여 준다.
- G2. 사용자가 결과를 확인·수정한 뒤 클릭 한 번으로 가리고, EXIF를 제거한 사본을 저장하게 한다.
- G3. 사용자의 원본 사진을 서버에 남기지 않는다.
- G4. 위 기능이 실제로 촬영한 사진에서 동작하는 정도를 측정 가능한 기준으로 검증한다.

**비목표**

- 자동으로 가려서 올려 주지 않는다. 무엇을 가릴지는 사용자가 확인하고 정한다.
- 얼굴 탐지·블러는 다루지 않는다. 기존 SNS 기능이 다루며 발표안의 탐지 대상이 아니다.
- 일괄 검사·노출 통계·온디바이스(로컬) 모드·SNS 공유 연결은 필수 범위가 아니다. 핵심 흐름이 끝난 뒤 여력이 있을 때 다룬다.

## 4. 사용자와 시나리오

| 사용자 | 사진을 공유하는 상황 | 필요한 보호 |
|---|---|---|
| 일반 사용자 | SNS·중고거래에 일상·물품 사진 공유 | 배경의 주소·연락처 노출 예방 |
| 직장인·학생 | 업무 자료·학습 화면 공유 | 문서·메신저·신원 정보 확인 |
| 기관 담당자 | 홍보 이미지를 대외 배포 | 공개 전 개인정보 노출 점검 |

**대표 시나리오 — 중고거래 사진 검사** (책상 위 노트북을 촬영해 올리려는 사용자)

1. 사진 입력: 노트북 사진을 웹에 올린다.
2. 자동 분석: 글자를 읽고 개인정보를 판정한다.
3. 위험 알림: 발견한 정보와 근거를 본다. 예시 문장(발표용): "오른쪽 아래 택배 송장에서 주소와 전화번호 발견"
4. 위치 확인: 빨간 박스를 확인하고 필요하면 수동으로 조정한다.
5. 안전 저장: 가림 처리와 EXIF 제거가 끝난 사진을 내려받는다.

**최종 시연(90초)**: 심사자·청중이 자기 사진을 올린다 → 본인이 놓친 영역을 탐지한다 → 위치와 근거를 확인한다 → 가림·EXIF 제거본을 저장한다.

## 5. 기능 요구사항

담당은 [ROLES.md](ROLES.md)의 역할 번호입니다.

### 필수

| ID | 요구사항 | 수락 기준 | 담당 |
|---|---|---|---|
| FR-01 | 사진 업로드: 선택·드래그, 미리보기. 형식은 jpeg·png·webp·heic | 지원하지 않는 형식·용량 초과·열 수 없는 파일은 이유를 안내한다 | 4·5 |
| FR-02 | EXIF 검사: GPS·기기·촬영 시각 등을 읽어 위험도를 표시 | GPS가 있는 사진은 촬영 위치 노출을 경고한다 | 4 |
| FR-03 | 개인정보 탐지: 사진 속 글자를 읽고 개인정보 유형과 원본 이미지상의 위치를 반환. 우선 유형은 전화번호·이메일·주소·이름 (스키마 `PIIType`에는 그 밖의 유형도 정의돼 있음) | 정해진 형식의 결과를 함수 호출 한 번으로 받을 수 있다 | 3 |
| FR-04 | 근거와 상태: 유형·위치·근거 문장을 주고, 판독 불가·판정 불확실을 구분. 신뢰도를 줄 때는 OCR 신뢰도인지 판정 신뢰도인지 밝힌다 | 예: "전화번호 형식의 문자열 발견". 읽히지 않는 영역은 '판독 불가'로 표시한다 | 3 |
| FR-05 | 위험도: 유형 × 판독가능성 × 면적으로 점수와 등급(none·low·medium·high)을 산정 | 산식·임계값을 3번이 확정해 문서에 기록한다 (D-11) | 3 |
| FR-06 | 결과 확인·편집: 사진 위 박스 표시, 목록과 박스 연결, 놓친 영역 추가·잘못 검출된 영역 삭제·이동·크기 변경, 가릴 영역 선택·해제 | 확대·축소·세로 사진에서도 박스가 제 위치에 있다 | 5 |
| FR-07 | 가림·저장: 선택한 영역을 가리고 EXIF를 제거한 파일을 내려받는다 | 화면의 박스와 결과 파일의 가림 위치가 같다. 결과 파일에 EXIF가 없다(자동 검사). 처리 위치는 미정 (D-05) | 4·5 |
| FR-08 | 원본 비저장: 원본·임시·결과 파일의 보관·삭제 시점을 정하고 정상·실패·취소 모두 정리 | 정한 시점이 지나면 원본이 서버에 남지 않는다 | 4 |
| FR-09 | 오류·빈 결과 처리: 분석 실패, 시간 초과, 결과 없음, 일부 판독 실패를 안내 | 사용자가 다음에 할 일을 알 수 있다 | 4·5 |

### 조건부 (측정으로 필요가 확인될 때 도입)

- 객체 검출(YOLO + SAHI): 객체 전체(송장·학생증 등)를 찾아야 하는 필요가 확인될 때
- NER: 규칙만으로 주소·이름 판정이 부족한 사례가 확인될 때
- 추가 학습·합성 데이터 생성기: 기존 모델로 해결하기 어려운 문제가 확인될 때

도입 여부는 2번의 평가 결과로 판단하고, 도입 전후를 같은 데이터로 비교합니다.

### 확장 (필수 아님)

일괄 검사(위험 사진만 추리기), 노출 유형 통계·인식 개선 화면, 서버 저장 없는 온디바이스·로컬 모드, SNS 공유 연결

| 협업 | `main`에 직접 push하지 않고 브랜치 + PR + 리뷰 1인 승인을 거친다 |

## 7. 동작 방식 (개요)

업로드 → EXIF 파싱·방향 보정 → OCR로 글자·좌표 추출 → 개인정보 판정(정규식·문맥 규칙) → 글자와 위치 연결 → 근거·위험도 생성 → 사용자 확인·수정 → 가림·EXIF 제거 → 다운로드

흐름의 세부, 모듈 경계, 기술 스택은 [ARCHITECTURE.md](ARCHITECTURE.md)를 봅니다.

## 8. 데이터와 평가

- **데이터**: 가상 정보를 넣은 송장·학생증·문서·화면을 직접 촬영하고, 사진마다 정답(개인정보 유형, 위치, 정답 문자열, 판독 가능 여부)을 만든다. 개발·학습용 / 튜닝 검증셋 / 최종 테스트셋을 나누고, 같은 소품·양식·장면의 유사 사진은 같은 묶음에 둔다(누수 방지). 타인의 개인정보가 담긴 이미지는 수집하지 않는다.
- **합성 데이터**: 발표안의 합성 파이프라인(HTML 템플릿 렌더링 → 왜곡 증강 → 실제 배경에 합성 → 합성 좌표를 그대로 정답으로 사용)은 추가 학습이 필요해졌을 때 우선순위를 판단한다.
- **평가**: 유형별 정밀도·재현율, 비위험 사진 오탐률, 처리 시간을 같은 데이터·같은 모델 버전으로 재현 가능하게 측정한다. 실패는 4종으로 분류해 원인 담당자에게 넘기고, 최종 보고에서 초기 버전과 개선 버전을 비교한다.
- 세부 업무는 [ROLES.md](ROLES.md)의 1·2번 항목을 봅니다.

## 9. 성공 기준 (목표이며 결과가 아님)

아래 수치는 검증할 **목표**입니다. 측정하기 전에는 달성했다고 쓰지 않습니다.

| 항목 | 목표 | 측정 방법 | 비고 |
|---|---|---|---|
| 객체 검출 mAP@0.5 | 80% 이상 | 실사 테스트셋 300장 | 객체 검출을 도입할 때만 해당 (D-04) |
| 개인정보 항목 재현율 | 85% 이상 | 유형별 개인정보 항목을 정답과 수동 대조 | 평가 범위 정의 필요 (D-10) |
| 비위험 사진 오탐률 | 15% 이하 | 비위험 사진 100장 | 300장에 포함인지 미정 (D-04) |
| EXIF 제거율 | 100% | 자동 검사 스크립트 | 검증용 샘플 담당 미정 (D-07) |
| 평균 분석 시간 | 5초 이내 | 4000px 사진, 실행 환경 함께 기록 | 지향 3초 |

## 10. 일정 (발표안, 재조정 필요 — D-09)

| 단계 | 기간 | 내용 | 완료 기준 |
|---|---|---|---|
| P0 | 3일 | 설계: JSON 스키마 확정, OCR 3종 벤치마크 | 기술 검증 통과 여부 결정 |
| P1 | 1.5주 | 합성 생성기, YOLO 1차 학습, EXIF 모듈 | 검출 mAP 초기값 확보 |
| P2 | 1주 | 타일 추론 적용, 크롭 OCR 연결 | 첫 End-to-End 동작 |
| P3 | 1주 | 정규식·NER 판정, 위험도 산정 엔진 | 판정 결과 JSON 완성 |
| P4 | 1주 | 프론트 오버레이, 마스킹 편집기 | 중간 점검 데모 |
| P5 | 1주 | 실사 평가, 오탐 임계값 튜닝 | 성능 지표 측정 완료 |
| P6 | 0.5주 | 시연 영상, 문서화, 최종 발표 준비 | 최종 산출물 제출 |

- 위 일정은 YOLO·합성 데이터 우선 계획이라 OCR 우선 방침에 맞춰 다시 짜야 합니다.
- 5인 분담안의 첫 주 공동 목표는 "사진 한 장이 처음부터 끝까지 처리되는 것"입니다.

**P0 기술 검증 계획 (발표안)**: 세 검증 모두 공개 이미지와 팀원 촬영본만 씁니다.

| 검증 | 데이터 | 비교 | 측정 |
|---|---|---|---|
| OCR 엔진 | 송장·학생증 사진 각 20장 | PaddleOCR / 외부 API / Tesseract | 문자 정확도, 처리 시간 |
| 타일 추론 | 고해상도 사진 30장 | 전체 리사이즈 vs SAHI 타일 | 검출 수·누락률, 처리 시간 |
| 주소 인식 | 도로명 주소 200건 | 정규식 vs 정규식 + NER | 주소·이름·전화 추출 성공률 |

Go/No-Go: 한국 택배 송장의 주소를 판독하지 못하면 설계를 재검토합니다.

## 11. 위험과 대응

| 위험 | 내용 | 대응 |
|---|---|---|
| 작은 글자 판독 (최대 불확실성) | 배경에 작게 찍힌 글자를 읽지 못한다. 4000px 사진을 모델 입력 크기로 줄이면 송장 글자가 사라진다 | 원본 해상도·분할(타일) OCR 비교, 판독가능성에 따른 점수 차등 |
| 학습 데이터 부족 | 한국 송장·학생증 공개 데이터셋이 없다 | 가상 정보로 직접 촬영·라벨링, 필요하면 합성 생성 |
| OCR 성능 미달 | 흐릿한 배경 글자의 주소·연락처 판독 실패 | 판독가능성 게이팅, 외부 OCR API 대체 검토 (D-06) |
| 오탐 과다 | 안전한 사진까지 위험으로 표시 | 유형별 임계값 분리, 실사 테스트셋으로 튜닝. 간판·책 표지·타인 SNS 화면 등은 오탐 사례로 따로 점검 |

## 12. 최종 산출물

- 배포된 웹 서비스
- 데이터셋·라벨링 기준서, 실사 평가셋, 평가 코드·오류 목록·성능 보고서
- OCR·개인정보 판정 모듈 (필요 시 학습된 검출·판정 모델, 합성 데이터 생성기)
- 시연 영상과 개발 문서

## 13. 용어

| 용어 | 뜻 |
|---|---|
| PII | 개인정보(Personally Identifiable Information). 이름·주소·전화번호·이메일·주민등록번호·카드번호 등 |
| OCR | 이미지 속 글자를 읽어 텍스트와 위치를 얻는 기술 |
| NER | 문장에서 이름·주소 같은 개체를 찾는 모델. 후보는 KoELECTRA NER |
| EXIF | 사진 파일에 들어 있는 메타데이터(GPS 좌표, 촬영 기기, 촬영 시각 등) |
| SAHI / 타일 추론 | 큰 사진을 작은 조각(타일)으로 나눠 각각 분석하고 결과를 합치는 방법. 작은 물체·글자를 놓치지 않으려는 목적 |
| NMS | 겹쳐서 중복 검출된 박스를 하나로 정리하는 후처리 |
| YOLO | 사진에서 물체의 종류와 위치를 찾는 객체 검출 모델 |
| 판독가능성 (readability) | 찍힌 글자를 실제로 읽을 수 있는 정도. 위험도 산정에 곱해진다 |
| GT(정답) | 사람이 만든 기준 답. 평가에서 AI 결과와 비교한다 |
| 오탐 / 누락 | 없는 것을 있다고 한 것 / 있는 것을 놓친 것 |
| 정밀도 / 재현율 | 찾은 것 중 맞은 비율 / 찾아야 할 것 중 찾은 비율 |
| IoU | 두 박스가 겹치는 정도(겹친 넓이 ÷ 합친 넓이). 위치가 맞았는지 판단하는 데 쓴다 |
| mAP@0.5 | IoU 0.5 기준의 객체 검출 평균 정밀도. 검출기 성능 지표 |
| 마스킹 | 개인정보 영역을 가리는 처리 |
