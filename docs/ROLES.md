# 역할 분담 (5인)

- 기준: 5인 역할 분담안 (2026-10-01 기준). 담당자 이름은 팀에서 아래 표에 적어 두세요.
- 구현 방침은 **OCR 우선**입니다. 기존 OCR로 글자와 좌표를 얻고 정규식·문맥 규칙으로 판정하는 것부터 만들고, YOLO·NER·합성 데이터·추가 학습은 측정으로 필요가 확인될 때 도입합니다.
- 1·2번은 2명이 함께 맡습니다. 초반에는 촬영·라벨링을 같이 하고, 중후반에는 한 명이 평가·통합 테스트를 책임집니다.
- 각 역할의 "관련 미결"은 [DECISIONS.md](DECISIONS.md)의 항목입니다. D-09(일정)는 모든 역할에 공통입니다.

| # | 담당 | 핵심 책임 | 최종 산출물 | 주 작업 폴더 |
|---|---|---|---|---|
| 1 | 데이터 구축 | 어떤 사진과 정답으로 개발할지 준비 | 데이터셋 · 라벨링 기준서 | `data/` |
| 2 | 평가 · 통합 지원 | 무엇이 잘못됐고 얼마나 개선됐는지 확인 | 평가 코드 · 오류 목록 · 성능 보고서 | `data/` |
| 3 | AI 분석 | 사진에서 개인정보와 위치를 찾아 반환 | OCR · 개인정보 판정 모듈 | `reader/`, `poc/` |

## 1번 — 데이터 구축

사진을 모으는 것뿐 아니라 **각 사진에서 무엇을 찾아야 하는지 정답까지 만드는 역할**입니다.

- **데이터 기준**: 우선 탐지할 유형(전화번호·이메일·주소·이름 등)을 정리합니다. 이름처럼 문맥이 필요한 항목은 어떤 경우에 개인정보로 표시할지 합의합니다. 글자가 읽히는 경우 / 일부만 읽히는 경우 / 판독 불가를 구분합니다.
- **촬영·수집**: 가상 정보가 들어간 송장·학생증·문서·화면을 준비하고, 거리·각도·조명·배경·글자 크기를 바꿔 촬영합니다. 간판·책 표지처럼 개인정보가 아닌 글자가 있는 사진도 확보합니다.
- **정답 라벨**: 개인정보 유형, 위치(박스 또는 다각형), 읽을 수 있는 정답 문자열, 판독 가능 여부.
- **분리·관리**: 개발·학습용, 튜닝용 검증셋, 최종 테스트셋을 나눕니다. 같은 소품·양식·촬영 장면의 유사 사진은 같은 묶음에 둡니다. 파일 이름·출처·사용 조건·수정 이력을 관리합니다.
- **보강**: 3번이 "작은 전화번호를 자주 놓친다"처럼 알려 주면 그 사례를 더 모읍니다. 합성 데이터 생성기는 추가 학습이 필요해졌을 때 우선순위를 판단합니다.

**처음 할 일**: 대표 사진 30~50장을 초기 점검용으로 준비하고, 개인정보의 위치와 유형을 표시합니다.
**완료 기준**: 다른 팀원이 사진과 정답을 받아 별도 설명 없이 개발·평가에 쓸 수 있습니다.
**관련 미결**: D-01, D-03, D-04, D-07, D-08, D-10

## 2번 — 평가 · 통합 지원

'남는 일을 돕는 사람'이 아니라 **평가 결과와 오류 재현을 책임지는 사람**입니다.

- **초반 데이터 지원**: 촬영과 라벨링을 나눠 맡고, 1번이 만든 정답을 검수합니다. 애매한 라벨은 함께 확인해 기준서에 반영합니다.
- **평가 기준**: 개인정보를 '찾았다'고 인정할 조건을 정합니다. 위치가 맞았는지와 문자열까지 정확히 읽었는지를 구분하고, 사진 단위 오탐과 개인정보 항목 단위 누락을 구분합니다.
- **평가 코드**: AI 결과와 정답을 비교해 유형별 정밀도·재현율, 비위험 사진 오탐률을 집계하고 처리 시간과 실행 환경을 기록합니다.
- **실패 사례 분류**: ① 글자 위치를 못 찾음 ② 위치는 찾았지만 글자를 잘못 읽음 ③ 글자는 맞게 읽었지만 개인정보 판정에 실패 ④ 분석은 맞는데 화면이나 저장 결과가 잘못됨.
- **통합 테스트**: 업로드부터 다운로드까지 전체 흐름을 확인합니다. 큰 사진·세로 사진·결과 없음·분석 실패 같은 상황을 점검하고, 사용자 편집 결과와 최종 파일이 일치하는지 봅니다.
- **최종 보고**: 초기 버전과 개선 버전을 비교하고, 개선된 사례와 남은 한계를 정리하고, 발표용 성능 표와 사례를 준비합니다.

**처음 할 일**: 정답 검수 기준과 오류 기록 양식을 만들고, AI 결과를 비교할 평가 코드의 틀을 작성합니다.
**완료 기준**: 같은 데이터와 모델 버전으로 평가하면 같은 결과가 재현되고, 실패 사례를 담당자가 바로 확인할 수 있습니다.
**관련 미결**: D-01, D-02, D-03, D-04, D-05, D-07, D-10

## 3번 — AI 분석

**이미지를 받아 개인정보 유형·위치·판정 근거를 반환하는 기능 전체**를 맡습니다. 처음부터 모델을 직접 학습할 필요는 없습니다.

- **OCR 실행·비교**: 기존 OCR을 연결해 글자와 좌표를 추출하고, 초기 점검 사진으로 판독 성능을 확인합니다. 속도와 메모리 사용도 함께 기록합니다.
- **개인정보 판정**: 전화번호·이메일 등은 정규식으로 먼저 구현합니다. 주소·이름은 주변 문맥과 규칙을 적용합니다. 규칙만으로 부족한 사례가 확인되면 NER 등 추가 방법을 비교합니다.
- **텍스트와 좌표 연결**: 여러 줄로 나뉜 주소를 하나의 항목으로 묶고, 개인정보 문자열을 원본 이미지 위치와 연결하고, 같은 항목의 중복 검출을 정리합니다.
- **결과와 설명 생성**: 유형과 위치, 근거(예: "전화번호 형식의 문자열 발견"), 판독 불가·판정 불확실 상태를 구분해 제공합니다. 신뢰도를 제공한다면 OCR 신뢰도인지 판정 신뢰도인지 밝힙니다.
- **실패 원인 개선**: 작은 글자 문제면 원본 해상도·분할 OCR 등을 비교하고, 문자 오인식이면 전처리·OCR 모델 변경을 검토하고, 의미 판단 문제면 규칙·NER을 개선합니다.
- **조건부 추가 학습**: 기존 모델로 해결하기 어려운 문제가 확인됐을 때 수행합니다. YOLO도 객체 전체를 찾아야 하는 필요가 확인되면 도입하고, 변경 전후를 2번의 평가로 비교합니다.

**처음 할 일**: 사진 한 장을 입력하면 OCR 결과와 개인정보 후보 좌표가 나오는 최소 모듈을 만듭니다.
**완료 기준**: 백엔드 담당자가 함수 하나를 호출해 정해진 형식의 분석 결과를 받을 수 있습니다.
**관련 미결**: D-01, D-02, D-03, D-06, D-11

## 4번 — 백엔드

**사용자의 요청을 받아 분석하고, 수정된 영역을 실제 파일에 반영하는 서비스 흐름**을 맡습니다.

- **API 설계**: 이미지 업로드·분석 요청, 분석 상태·결과 조회, 사용자가 수정한 영역 제출, 보호 처리된 이미지 다운로드, 입력 오류·분석 실패 응답.
- **AI 모듈 연결**: 이미지 전처리와 분석 모듈 호출 순서를 정리하고, 작업 ID·상태·결과를 관리합니다. 타임아웃과 동시 실행 수를 제한하고 요청 취소·실패 상황을 처리합니다.
- **마스킹·EXIF 처리**: 사용자가 선택한 최종 좌표에 가림 처리를 하고, 지원 형식의 EXIF를 제거합니다. 화면의 박스가 출력 파일의 같은 위치에 적용되는지 확인합니다. (처리 위치 미정, D-05)
- **파일 생명주기**: 원본·임시 파일·결과 파일의 보관·삭제 시점을 정의하고, 정상 완료뿐 아니라 실패·취소 때도 정리합니다. 민감한 OCR 원문이 로그에 남지 않게 합니다.
- **기록·배포**: 필요하면 작업 시간·오류 유형·모델 버전 등을 DB에 기록합니다. 서버 실행 환경과 설정을 관리하고 배포·실행 문서를 씁니다.

**처음 할 일**: 실제 AI 대신 고정된 예시 결과를 반환하는 API를 만들어 프론트엔드와 연결합니다. (목업은 이미 `server/mock_app.py`에 있음)
**완료 기준**: 화면 없이 API만 호출해도 업로드부터 마스킹된 파일 다운로드까지 가능합니다.
**관련 미결**: D-01, D-05, D-06, D-07

## 5번 — 프론트엔드

**사용자가 탐지 결과를 이해하고 잘못된 부분을 수정할 수 있는 화면**을 맡습니다.

- **업로드·진행 화면**: 사진 선택·드래그 업로드, 파일 미리보기, 분석 진행·완료·실패 상태 표시.
- **결과 표시**: 사진 위에 개인정보 영역을 표시하고, 유형과 근거 목록을 제공하고, 목록에서 고른 항목과 사진의 박스를 연결합니다.
- **영역 편집**: 놓친 영역 직접 추가, 잘못 검출된 영역 삭제, 박스 이동·크기 변경, 가릴 영역 선택·해제.
- **좌표 변환**: 원본 이미지 좌표를 화면 크기에 맞게 표시하고, 사용자가 화면에서 수정한 좌표를 원본 좌표로 되돌립니다. 확대·축소와 세로 사진에서도 위치가 맞는지 확인합니다.
- **미리보기·저장**: 마스킹 미리보기, 최종 영역을 백엔드에 전송, 처리된 파일 다운로드. (처리 위치 미정, D-05)
- **사용성·시연**: 결과가 없거나 일부 판독에 실패했을 때의 안내를 만들고, 다른 팀원에게 써 보게 해 혼동되는 부분을 고칩니다. 발표용 사용자 흐름과 시연 화면을 준비합니다.

**처음 할 일**: 예시 사진과 가짜 검출 좌표로 업로드·결과 표시·박스 수정 화면을 만듭니다.
**완료 기준**: 다른 사람이 설명 없이 사진을 올리고, 영역을 확인·수정하고, 저장할 수 있습니다.
**관련 미결**: D-01, D-05

## 겹치는 일의 경계

| 업무 | 주담당 | 협업 방식 |

## 협업 흐름

- **첫 주 공동 목표**: 사진 한 장이 처음부터 끝까지 처리되는 것. 1·2번이 소규모 데이터와 정답을 만들고, 3번이 OCR과 간단한 판정을 연결하는 동안, 4·5번은 예시 결과로 API와 화면을 개발합니다.
- **첫 통합 이후**: 2번이 실패 사례를 찾고 → 3번이 원인을 분석하고 → 1번이 필요한 데이터를 보강합니다.
