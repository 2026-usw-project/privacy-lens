# 이미지 객체(얼굴·증명사진·번호판) 작업 기록 (2026-11-02 ~ 11-04)

D-16 으로 YOLO 의 역할을 '글자가 아닌 이미지 객체'로 옮긴 뒤 한 일을 순서대로 적는다. 숫자는 모두 측정한 것이고, 어떤 사진으로 쟀는지 함께 적었다.
자세한 표는 [vision/README.md](../vision/README.md), 결정은 [DECISIONS.md](DECISIONS.md) D-16·D-18.

## 한 줄 요약

- **번호판**: 한국 주차장 실사 재현율 0.54(공개 모델) → **0.78**(우리 v003 + 돌려 찾기). 서버 추천 모델 v003.
- **증명사진(얼굴)**: 처음 보고한 정밀도 0.606 은 평가 실수였다(바로잡으면 0.91). 진짜 약점은 **누운 사진**이었고, 돌려 찾기로 누운 사진 재현율 0.04~0.11 → **0.80~0.82**.
- 두 경우 모두 "회전 정보(EXIF)가 빠진 채 90도 누운 사진"이 가장 큰 원인이었다.

## 1. 처음 상태 (11-02)

- 얼굴: OpenCV YuNet(학습 없음). 증명사진 = 얼굴 + 카드 단서(학생증 상자, 근처 '학생증·성명' 글자, 이름·학번 항목).
- 번호판: 공개 YOLO26 번호판 모델(ONNX, AGPL)과 Open Images 로 직접 학습한 v001 을 Open Images 검증 300장으로 비교 → v001 이 더 많이 찾음(재현율 0.876 대 0.744).
- 이때 YuNet 정밀도가 0.606 으로 나와 "얼굴이 부정확하다"고 보고했다.

## 2. 평가 방식 바로잡기 (11-02 밤)

- 0.606 은 **평가 코드의 실수**였다. 20px 미만 얼굴을 정답에서 빼 놓고 그 얼굴을 찾은 것은 오탐으로 셌고, Open Images 의 '여러 얼굴을 한 상자로 묶은 라벨' 안의 얼굴도 오탐으로 셌다.
- COCO·WIDER 처럼 이런 것은 '무시'로 세게 고쳤다(`vision/objects_eval.py`). 다시 재니 기준 0.7 에서 정밀도 0.910·재현율 0.780.
- 기준값을 바꿔 가며 재고 **0.7 → 0.6** 으로 내렸다(F1 같고 놓침 감소, 원칙: 놓침이 오탐보다 나쁘다).

## 3. 한국 번호판 (11-03 오전)

- 바로 쓸 수 있는 한국 번호판 검출 데이터가 없었다. AI 허브는 번호판만 잘라 둔 사진, Hugging Face 는 빈 저장소였다.
- Roboflow 에서 CC BY 4.0 데이터 3개를 찾았고, 찬영이 로그인해 받았다(드라이브 `objects/kr/`, 저장소 금지).
  - 평가: hyunjin/korea-car-license-plate — 주차장 실사, 증강 사본을 뺀 원본 207장(번호판 259개). **학습에 쓰지 않는다.**
  - 학습: bowontron/license-plate-label 3,035장, korean-car-plat 1,000장 — 번호판을 가까이 찍은 사진.
- 결과(확신도 0.4 재현율): 공개 0.537, v001 0.490. **해외 사진으로만 학습한 모델은 한국 번호판을 절반도 못 찾았다.**
- v002(한국 사진 추가 이어 학습) 0.626. 학습 도구가 해외 검증 점수로 최고 모델을 골라 epoch 1 이 뽑히는 문제가 있어 마지막 가중치를 쓰게 고쳤다.

## 4. 놓친 번호판 직접 보기 → 누운 사진 발견

- v002 가 놓친 번호판을 잘라 모아 보니(드라이브 `objects/kr_missed_v002.jpg`) 번호판이 옆으로 누운 사진이 많았다.
- 평가 사진 207장 중 **61장(30%)이 EXIF 회전 정보 없이 90도 누워 있었다.** 이런 사진에서는 모든 모델이 재현율 0.01~0.2.
- 서비스는 EXIF 를 적용해 사진을 바로 세우므로 실제 사용에서는 덜 나쁘다. 하지만 메신저처럼 회전 정보를 지우는 경로로 온 사진은 정말 누워서 들어온다.

## 5. v003(합성)과 돌려 찾기

- 한국 학습 사진이 '가까이 찍은 번호판'뿐이라, 진짜 한국 번호판 조각 2,168개를 Open Images 차량 장면의 번호판 자리에 붙인 합성 사진 1,644장을 만들었다(`vision/plate_synth.py`). → v003.
- v003: 바로 선 한국 사진 0.827(가장 높음), 해외 0.859(v002 에서 떨어졌던 것 회복). 한국 전체는 0.618 로 v002 와 비슷 — 합성 효과는 작았다.
- **돌려 찾기**: 번호판 검출을 0·90·270도로 해서 합친다(`PL_PLATE_ROTATE`, 기본 켬). 한국 전체 0.618 → **0.784**, 누운 사진 0.15 → 0.66. 대신 정밀도 0.865 → 0.784, 번호판 검출 시간 약 3배.

## 6. 증명사진을 우리 용도로 재기 (11-03 오후)

- Open Images 얼굴은 '사람 사진'이라 우리 용도(사진 속 신분증의 작은 증명사진)와 다르다. 신분증 얼굴은 흑백·작은 인쇄·반사·기울기 때문에 일반 검출기가 약하다는 연구가 있다(arXiv:1911.03567).
- MIDV-2020 photo(가상 신분증 10종 1,000장, CC BY-SA 2.5, 얼굴은 생성 얼굴, 등록 없는 FTP)로 쟀다(`vision/face_eval.py`).
- 바로 선 사진: 재현율 0.76, 1/8 로 줄여 얼굴 32px 이어도 0.65. **90도 누우면 0.13 이하.**
- 얼굴도 돌려 찾게 했다(`PL_FACE_ROTATE`, 기본 켬). 같은 150장: 누운 사진 0.04~0.11 → 0.80~0.82, 바로 선 사진 0.82 그대로, 정밀도 −0.1 정도.
  기본 모드(card)는 카드 단서가 있어야 알리므로 늘어난 오탐이 그대로 화면에 나가지는 않는다.
