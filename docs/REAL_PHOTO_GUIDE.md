# 실사 평가 가이드 (1차)

1차 목표(`docs/PLAN_1ST.md`)를 숫자로 확인하려고 팀원이 직접 찍은 사진으로 지금 서비스를 잰다.
**사진·정답은 저장소에 올리지 않는다.** 팀 구글 드라이브 `PrivacyLens-Eval/` 에만 둔다.

## 1. 무엇을 몇 장 찍나

| 장면 | 장수 | 무엇을 바꿔 찍나 |
|---|---|---|
| 송장(라벨 있음·없음) | 6 | 상자 위 / 손에 든 것 / 바닥에 놓인 것, 1m 이상 떨어져 작게 |
| 학생증·사원증·명찰 | 4 | 책상 위, 목걸이에 걸린 것, 책장에 꽂힌 것(작게) |
| 카드·가상 신분증 | 3 | 반사광, 비스듬히 |
| 메모·포스트잇 | 3 | 모니터 옆, 냉장고 |
| 명함 | 2 | 지갑 옆, 여러 장 겹쳐서 |
| 화면(메일·메신저·모니터) | 4 | 모니터를 폰으로 찍기, 캡처 이미지 |
| 영수증 | 2 | 구겨진 것 |
| 가릴 것이 없는 사진(간판·메뉴·책 표지) | 6 | **오탐 확인용.** 이름처럼 생긴 상호, 가게 번호 |
| **합계** | **30** | |

- 한 장면을 비슷하게 여러 장 찍지 않는다. 같은 소품·같은 자리면 1장으로 친다.
- 일부러 어렵게 찍는 사진(멀리·기울임·반사)을 3분의 1 정도 섞는다. 쉬운 사진만 있으면 숫자가 실제보다 좋게 나온다.
- **찍는 사람과 규칙을 고치는 사람을 나눈다.** 고치는 사람이 시험 사진을 보면서 규칙을 맞추면 숫자가 부풀려진다.

## 2. 개인정보 다루는 법

두 가지 중 하나로만 찍는다.

1. **촬영용 소품(권장)**: `python -m samples.props <폴더>` 로 만든 `소품_인쇄용.pdf` 를 A4 **실제 크기(100%)** 로 인쇄해 자른다.
   글자가 전부 가짜라 가릴 필요가 없고, 정답이 `props.json` 에 미리 들어 있다.
2. **본인 물건**: 이름·번호를 포스트잇이나 마스킹테이프로 가리고 찍는다. 가린 글자는 정답에 적지 않는다.

- 다른 사람의 물건은 찍지 않는다. 가족·친구 것은 동의를 받고 2번 방식으로만.
- 공유 폴더에 올리기 전에 위치정보를 지운다: `python -m eval.failures strip <폴더>`
- 인쇄물은 실제 송장(감열지)·카드(플라스틱)와 질감이 다르다. 그래서 2번 사진도 몇 장 섞는다.

## 3. 폴더

```
PrivacyLens-Eval/
├── 실사-개발용/        규칙을 고치는 사람이 봐도 되는 사진(10장)
│   ├── cy_001.jpg      찍은사람_번호
│   ├── cy_001.json     정답
│   ├── props.json      촬영용 소품 정답(소품을 쓴 경우)
│   ├── 정답입력도구.html
│   └── 평가기록.csv     평가할 때마다 한 줄씩 쌓인다
└── 실사-시험용/        숫자만 보는 사진(20장). 1차 측정 뒤에는 사진을 바꾸지 않는다
```

나중에 사진을 더 모으면 `실사-2차/` 처럼 새 폴더를 만든다. 기존 시험용 폴더에 섞으면 전후 비교가 깨진다.

## 4. 정답 입력

1. `python -m eval.failures init <폴더>` (또는 Colab 노트북 2번 칸) → 폴더에 `정답입력도구.html` 이 생긴다.
2. 크롬·엣지로 그 파일을 열고 **폴더 열기**로 같은 폴더를 고른다. 사진은 컴퓨터 밖으로 나가지 않는다.
3. 사진마다 **보이는 글자 그대로** 적고, 항목과 등급(가림 / 확인 필요 / 가리면 안 됨)을 고른다.
   - 소품을 찍었으면 '찍힌 소품 넣기'에서 번호(P01…)를 고르고, **사진에서 안 보이는 글자는 지운다.**
   - 주소처럼 여러 줄이면 줄마다 따로 적는다(도로명 / 동·호수).
   - 가릴 것이 없는 사진은 '가릴 것이 없는 사진'을 체크한다. 오탐을 세는 데 쓴다.
4. 기준은 `docs/MASKING_CRITERIA.md`. 애매하면 메모 칸에 적고 팀에서 정한다.
5. **두 번째 사람이 검수한다.** 정답이 틀리면 평가 숫자 전체가 틀린다.

## 5. 평가

Colab: `eval/colab_eval.ipynb` (0 → 1 → 3). 내 컴퓨터:

```bash
PL_OCR=paddleocr PL_YOLO=off python -m eval.failures run <폴더> --note "OCR만, 이름 규칙 보강 전"
PL_OCR=paddleocr PL_YOLO_WEIGHTS=<best.pt> python -m eval.failures run <폴더> --note "YOLO v004"
```

출력 읽는 법

| 결과 | 뜻 | 다음 행동 |
|---|---|---|
| ① 못 찾음 | OCR 결과에 비슷한 글자조차 없음 | 작은 글자·반사·기울기 사례 확인 → OCR 전처리, YOLO 다시 읽기 |
| ② 잘못 읽음 | 비슷한 글자는 있음(010 → O1O) | 숫자 보정(`kr_patterns.normalize`), OCR 모델 비교 |
| ③ 판단 실패 | 글자는 맞게 읽었는데 등급이 틀림 | 판단 규칙. 먼저 `python -m eval.judgment` 에 같은 유형 장면을 추가하고 고친다 |
| 정답 밖 가림 | 정답에 없는데 가림으로 올라옴 | 오탐이거나 정답에서 빠뜨린 것. 사진을 다시 본다 |

주의
- **③에는 '라벨을 못 읽어서' 판단을 못 한 경우도 섞인다.** 예: 회색 작은 '받는분'을 OCR 이 놓쳐 이름 판단 실패.
  틀린 사진을 `--show-text` 로 확인하면 구분된다(그 출력은 공유하지 않는다).
- 30장은 적다. 항목별로 보면 몇 개씩이다. 방향을 보는 숫자이지 정밀한 성능 수치가 아니다.
- `평가기록.csv` 에는 코드 버전(커밋)·OCR·검출 모델이 같이 남는다. 발표의 '개선 전/후' 표는 이 파일에서 만든다.
