# data/ — 합성 사진 · 평가

가상 정보로 만든 테스트 사진과, 그 사진으로 분석 결과를 채점하는 스크립트입니다. 사진은 git에 올리지 않습니다(`.gitignore`).

## 명령

```bash
# 개발셋: 기본 15장 + 어려운 비위험 6장 (규칙을 고치며 보는 세트)
python -m data.synth.compose --n 12 --neg 3 --hard 6 --out data/demo
# 보류 세트: 다른 seed — 규칙을 고치는 데 쓰지 않고 수치를 확인할 때만 사용
python -m data.synth.compose --seed 7 --n 12 --neg 3 --hard 6 --out data/test

python -m data.eval --dir data/demo                 # 채점 (결과 JSON도 <dir>/eval_result.json 에 저장)
python -m data.check_exif ~/Downloads/safe_*.jpg    # 저장본에 EXIF 가 남았는지 (제거율 100% 확인)
python -m pytest -q tests                           # 채점 로직 · EXIF 검사 · 알려진 오탐 테스트
```

Windows에서 OpenCV·torch가 "애플리케이션 제어 정책"으로 막히면(Smart App Control) WSL에서 실행합니다. 한글 폰트가 없으면 `PL_FONT` 에 `.ttf` 경로를 줍니다.
`--hard` 를 주지 않으면 사진이 예전과 똑같이 만들어집니다(난수를 따로 씀).

## 정답 `truth.json`

사진마다 `{file, negative, hard, has_gps, objects:[{label, bbox, pii:[{type, value}]}]}`.
채점은 `pii` 의 **값**을 씁니다. 실사 라벨링용 형식(항목별 박스·판독 여부·`group_id`)은 아직 정해지지 않았습니다(D-03).

## 채점 방식 (`data/eval.py`)

| 지표 | 뜻 |
|---|---|
| 재현율 · 정확 | 정답 값을 그대로 찾음. 숫자류는 숫자만 같으면, 글자류는 공백·쉼표를 뺀 문자열이 같으면 일치 |
| 재현율 · 허용 | 글자류(이름·주소·소속)는 글자 20% 이내(최소 1자) 오인식 허용 |
| 재현율 · 유형만 | 같은 유형이 하나라도 있으면 인정. 값을 안 보던 이전 방식이라 **비교용**으로만 봄 |
| 정밀도 | 찾은 항목 중 정답과 짝지어진 비율. 정답에 없는 항목(상호를 이름으로 잡는 등)이 오탐. OCR이 한두 글자 틀리게 읽은 값은 정확 모드에서 '놓침'이자 '오탐'으로 함께 셈 |
| 오탐(사진 단위) | 개인정보 없는 사진에서 medium 이상이 뜬 비율. 어려운 비위험은 따로 표시 |
| 응답 시간 | 모델 로딩을 뺀 값 |

정답과 예측은 1:1로 짝지어 센다(같은 번호 하나로 두 정답을 채울 수 없음).
값 비교는 서버 응답(마스킹됨)이 아니라 `reader.rules.find_pii` 의 원문 값으로 합니다. 서버 코드는 바꾸지 않고 OCR 줄을 가로채서 얻습니다(D-02의 (a)).

## 개발셋과 최종 수치

규칙을 이 합성 사진의 OCR 오인식으로 다듬었기 때문에 `data/demo` 점수는 **개발셋 점수**입니다. 최종 수치는 규칙을 고치는 데 쓰지 않은 세트로 재세요. 합성 사진은 실사보다 쉬우므로 실사 테스트셋으로 다시 재야 목표(재현율 85%, 오탐 15%)와 비교할 수 있습니다.

## 어려운 비위험 (정책 제안)

`--hard` 는 상호·대표번호·사업장 주소·ISBN·고객센터 번호처럼 개인정보로 오인하기 쉬운 글자만 있는 사진을 만듭니다. 이런 정보는 **개인정보가 아니라는 가정**으로 정답을 비워 둡니다. 이 가정은 D-10(탐지·평가 범위)에서 팀이 확정해야 하고, 다르게 정해지면 `templates.py` 의 `HARD` 를 바꿉니다.
